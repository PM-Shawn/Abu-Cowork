# v0.34.0 Post-Release Engineering TODO

This list preserves the broader review findings without expanding the
Tauri-to-Electron release scope. Items below are **not** v0.34.0 release
acceptance criteria unless production monitoring shows a regression.

## P1 — schedule immediately after the transition release

- **Browser Bridge lifecycle and identity**
  - Consolidate bridge locking, health checks, stale-owner recovery, and port
    diagnostics behind one manager shared by settings, MCP startup, and quit.
  - Add authenticated peer identity instead of relying only on same-user
    process inspection and command-shape checks.
  - Acceptance: repeated install/upgrade/restart and concurrent old/new Abu
    launches recover without killing unrelated listeners or asking users to
    find background processes manually.

- **HTML preview isolation architecture**
  - Replace directory-wide loopback origins with per-preview isolation (custom
    protocol or equivalent origin boundary).
  - Add explicit, user-visible permission for previews that need external
    assets. v0.34.0 intentionally blocks preview-origin network egress.
  - Acceptance: sibling outputs are not readable by an unrelated preview;
    external access is denied by default and auditable when enabled.

- **Secret writes become transactional UI operations**
  - Make provider and auxiliary-key edits await the encrypted-store write and
    show a recoverable error in the settings UI.
  - Remove the plaintext persistence fallback once durable retry/recovery is
    proven across macOS and Windows.
  - Acceptance: simulated safeStorage/Credential Manager failures never lose a
    key and never silently downgrade storage security.

- **Windows shell and layout regression matrix**
  - Centralize titlebar drag/no-drag regions, modal coverage, native menu,
    window controls, sidebar actions, and panel resize behavior.
  - Add packaged UI automation at 100%, 125%, and 150% scaling on Windows 10
    and 11; keep macOS traffic-light geometry in the same contract suite.
  - Acceptance: controls remain clickable and modals cover the full client area
    on every supported scale without per-screen CSS patches.

## P2 — hardening after release stability is confirmed

- **Trigger ingress authentication**: require an installation-scoped token (or
  stronger channel authentication) before allowing a trigger server to bind
  beyond loopback; rate-limit and audit rejected requests.
- **Cross-platform path corpus**: add Windows drive roots, UNC paths, reserved
  names, non-ASCII paths, symlink/junction cases, long paths, and macOS
  normalization to migration, archive extraction, opener, and workspace tests.
- **Updater observability and rollback**: freeze localized release notes with
  each feed, expose migration/update stage IDs in diagnostics, and document a
  tested Electron-to-Electron rollback procedure.
- **Usage accounting correctness**: reconcile retries, sidecar runs, subagents,
  and provider-specific cached/reasoning tokens against provider billing data.
- **Cross-process policy consolidation**: make run restrictions a single typed
  policy object shared by model-visible tool resolution, local sidecar tools,
  reverse RPC, and delegated work, reducing manual wire-field drift.
- **Release CI maintainability**: split the large release workflow into tested
  reusable actions/scripts while preserving transaction rollback and byte
  verification semantics.

## v0.34.0 release blockers handled in the release branch

- Custom-trigger `allowedTools` is enforced model-side, at execution, across
  the sidecar boundary, and in delegated subagents.
- Default-app opening no longer interpolates a path into an unsandboxed shell
  command fallback.
- Local HTML preview keeps relative assets/scripts but blocks external network,
  forms, nested frames, plugins, and popup escape paths.
- A post-bootstrap encrypted-secret write failure re-enables the data-preserving
  persistence fallback immediately instead of losing the edited key on restart.
