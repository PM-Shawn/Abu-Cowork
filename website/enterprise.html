Why Enterprise

Employees are already using AI, and the organization needs to manage it. Once AI reaches a team, the enterprise faces four management problems: cost, access, knowledge and risk.

1

AI spend becomes opaque

Every employee sets up a model key. Who uses AI, how much, and which department is over budget are hard for the enterprise to say.

Enterprise answer

Model calls all go through the enterprise gateway. Admins set budgets, RPM limits and allowed models per department, and review usage and cost in the console.

2

Access boundaries are unclear

Models, knowledge bases, Skills, MCP services and file access live in each person's settings, so the enterprise cannot apply one set of organization rules.

Enterprise answer

Admins draw the boundaries with organizations, departments, roles and pushed policies. The client checks locally before it calls a tool, a Skill or an MCP service.

3

Company knowledge stays buried

Policies, FAQs, product material, project documents and meeting notes sit in files, and AI cannot reliably cite the enterprise's own material.

Enterprise answer

Enterprise knowledge bases support document upload, parsing, chunking, vector search and full-text search. Abu can cite its sources when it answers, and every query is audited.

4

Tool sources and risk are hard to trace

Employees install extensions and connect internal systems on their own. Source, permission, credential, version and usage records are hard for the enterprise to manage in one place.

Enterprise answer

Skills go through upload, scan, review, publishing and signature checks. MCP services go through catalog registration, review, authorization and credential management. When something goes wrong, admins can trace it back.

Product shape

Enterprise adds a governance layer on top of Abu. Employees use AI in the desktop client, and admins configure organization, models, knowledge, tools and governance policies in a private console.

Employee side

Employees keep a familiar workflow

Employees still start tasks, call tools and use Skills in the Abu desktop client. After binding to the enterprise, the client uses enterprise models, enterprise knowledge bases and approved Skills, and shows each employee their own usage and audit information.

Core enterprise capabilities

Six modules: identity, cost, knowledge, extensions, security and operations. Each one states the problem it solves and what the console actually manages.

Identity

Identity and organization governance

The enterprise's organizations, departments, employees, roles and login methods are all managed in one console.

  • Password, Magic Link, OIDC SSO and desktop Device Flow
  • Organization, department tree, users, roles and permission matrix
  • Invites, pending approvals, sessions and license seats
Gateway

Model gateway and cost controls

Model keys, providers and spend that were scattered among employees come back to the enterprise side for central governance.

  • LiteLLM gateway, multiple providers, encrypted storage of the real keys
  • Department budgets, RPM limits, model allowlists and connectivity tests
  • Tokens, spend and calls by user, department and model
Knowledge

Enterprise knowledge bases

Once enterprise documents are ingested, Abu can search and cite them, and every query leaves an audit record.

  • PDF, Word, HTML, Markdown and plain-text ingestion
  • pgvector vector search + BM25 full-text search + RRF ranking
  • Organization, department and personal scopes with ACLs
Extensions

Trusted Skill and MCP extensions

Internal capabilities and connections to outside tools can all be published, authorized, signature-checked and traced.

  • Skill upload, manifest parsing, security scan, review and publishing
  • Skill ACLs, signature verification and client install records
  • MCP catalog sync, review, ACLs and authorized credential access
Policy

Security policies enforced locally

Organization-level and department-level policies are pushed to the client, which blocks a sensitive action or asks for confirmation before it happens.

  • Tool blocklist, tool confirmation rules, Skill / MCP blocklists
  • File path allowlists and blocklists
  • Enterprise policy hooks run before local tool calls
Ops

Audit, transparency and operations

Admins see the governance outcomes, and employees see which of their own data and usage the enterprise has recorded.

  • Admin audit logs, sensitive-field redaction, usage and cost dashboards
  • Employee transparency page: profile, tokens, audit, usage
  • Quality feedback, diagnostic logs, diagnostic bundles and a self-hosted observability entry

Deployment and delivery

Enterprise starts from a private single-host deployment, with the console deployed separately. The client's enterprise capabilities are delivered through enterprise builds and closed-source modules; private modules never enter the public release.

DeliveryPrivately deployed enterprise consoleThe standard single-host deployment includes Console, Postgres / pgvector, LiteLLM, Nginx, Redis, MinIO and related components; observability and knowledge-base enhancements can be enabled to suit the customer environment.
Scale50 to 2,000 seatsPoCs and teams of 50–500 can start with the default configuration; 500–2,000 seats should tune database, gateway and observability resources; larger environments get a separate high-availability design.
ComplianceRoom left for domestic IT environmentsThe database layer stays close to standard Postgres and images support amd64 / arm64; domestic databases, CPUs and intranet models can be validated against the real customer environment.

Open source and Enterprise

Both editions share the same core, and Enterprise adds organization-level governance. The open-source edition suits individuals and small teams; Enterprise suits organizations that need central control of cost, access, knowledge, extensions and audit.
